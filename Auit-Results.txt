## Critical (HIGH)

### 1. FS: Non-zero indirect block on allocation — `fs/file_io.c:66-86`
When an indirect zone is allocated, its 512 bytes are not zeroed; any non-zero 16-bit value is treated as a zone pointer without validation, leading to metadata corruption and cross-data exposure on writable volumes. This does not reproduce on the production ROM image (`make_minixfs.rb:71` zeroes it), but is a real bug on writable volumes. Fixed by zeroing the zone on allocation.

### 2. Platform: fork stack measurement rejects valid stacks >1 KB — `platform/zeta-v2/syscall_entry.s:227`
`cp #0x04` checks the high byte of the *length* (`0x8000 - (SP+2)`), not SP itself. Consequently, any stack deeper than 1024 bytes in window 1 is rejected, and the child receives the parent's stack — overwriting its frames. The check should be on the high byte of SP. (Verified 2026-10-14: the fork-stack block now lives at `platform/zeta-v2/syscall_entry.s:226-235`; the HIGH-2 fix below landed.)

### 3. Platform: window-0 guard reads saved registers, not return address — `platform/zeta-v2/context_switch.c:330-352`
The guard `muzix_zeta_caller_in_window0()` reads SP+2 (already pushed HL/DE), not the return address. It passes only because the current call sites put the argument in DE, whose high byte clears bits 14–15. A change to the calling side or argument width could bypass the guard and corrupt the map. (Verified 2026-10-14: the guard now reads offset 6 at `platform/zeta-v2/bank_io.s:39-51`; the HIGH-3 fix below landed.)

## Verified Invariants (held)

- Bank selectors 0x78–0x7B are **never read** — only `z80_outb`
- Temp-map switches preserve/restore **all four** windows
- Copy primitives refuse regions 0 and 3
- Tick handler is safe under any map (only windows 0 and 3)
- No `__mullong`/`__divulong` in kernel.map (`l__HOME = 0`)
- Syscall numbering 1–60 (with gaps) is consistent between `lib/syscall.h`, `kernel/syscalls.h`, and the dispatcher
- Userspace `_DATA` is **not** pinned to 0x9000 (historical bug fixed in all `.lk`)
- `crt0.s` loads argc→HL, argv→DE per SDCC convention
- ROM writes are silently dropped (not partial, not error)
- Path traversal does not escape mount root; buffers are bounds-checked; block size = 512 everywhere
- Page pool is limited to 0x20–0x3F; double-free is blocked (zeroing `owned_count` before release)

## Conclusion

The codebase is generally clean and demonstrates solid understanding of Z80/SDCC constraints. The HIGH issues are two real corruptors (indirect-block on writable volumes, fork-stack overflow) and two brittle guards (window-0, fork-measure). The MEDIUM findings mostly follow one pattern: **page release must be part of the teardown function, not a separate step for each caller** (`proc_table.c`, `syscalls.c`), and **missing rollback on flush failure** in FS.

# Remediation Plan

## HIGH (Critical) — first priority

### HIGH-1: fs/file_io.c — zero indirect block on allocation
- **File**: `fs/file_io.c:66-86`
- **Problem**: After `muzix_fs_zone_alloc()` for `inode->indirect_zone`, the block is not zeroed.
- **Fix**: After `muzix_fs_cache_get()`, add `memset(indirect, 0, MUZIX_FS_BLOCK_SIZE)` and `muzix_fs_cache_mark_dirty()`.
- **Status**: ✅ done

### HIGH-2: platform/zeta-v2/syscall_entry.s — fix fork stack check
- **File**: `platform/zeta-v2/syscall_entry.s:226-229`
- **Problem**: `cp #0x04` checks the high byte of the length, not SP.
- **Fix**: Replace with `ld a, d / cp #0x80 / jr C, fork_stack_done`.
- **Status**: ✅ done

### HIGH-3: platform/zeta-v2/bank_io.s — fix window-0 guard offset
- **File**: `platform/zeta-v2/bank_io.s:39-49`
- **Problem**: `muzix_zeta_caller_in_window0()` reads SP+2 (saved HL/DE), not the return address.
- **Fix**: Change offset from 2 to 6 (because `zeta_cross_bank_call_impl`/`zeta_with_temp_map_impl` push HL and DE before calling).
- **Status**: ✅ done

## MEDIUM (Significant)

### MED-1: kernel/proc_table.c — deliver_pending must release pages
- **File**: `kernel/proc_table.c:807-832`
- **Fix**: Add `muzix_proc_table_release_pages()` before `muzix_proc_table_exit_status()`.

### MED-2: kernel/syscalls.c — revert EXIT teardown order
